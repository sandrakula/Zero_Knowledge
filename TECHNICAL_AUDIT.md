## Карта межмодульных зависимостей

```text
Config + PostgreSQL + migrations + startup lifecycle
                  │
        Authentication / Users
                  │
Organizations ─ Membership / Roles / UserGroups / Feature & Plan Gates
                  │
       ┌──────────┼─────────────┐
       │          │             │
 Courses      Communities     Boards
   │  │            │             ├── Collab WebSocket
   │  ├── Assignments             ├── API membership + YDoc persistence
   │  ├── Certificates/Trails     └── Redis cache
   │  ├── Paths/Podcasts
   │  └── Search/RAG
   │
 Media / Storage ──► Courses, submissions, org branding, boards, podcasts, AI/RAG
   │
   ├── Redis queues/caches ──► RAG, HLS, captions, nudges, webhooks, auth/rate limits
   └── Email delivery ───────► auth, invites, drip, messaging, lifecycle nudges

Business services ──► analytics hooks / audit / webhooks
                   └► feature usage and plan checks

FastAPI OpenAPI ─► generated SDK types
Web source ──────► generated React activity renderer ─► Vue wrapper
```

### Скрытые общие зависимости

- **Организация — базовая граница данных.** `org_id` повторяется в большинстве моделей; tenant context участвует в auth, custom domains, RBAC, feature gating, API token scope и Web URL resolution.
- **RBAC и user groups — не только административная функция.** `Role.Rights` содержит права на courses, media, assignments, boards, discussions и другие ресурсы. `UserGroupResource` связывает группы с защищёнными ресурсами; `resource_access.py` обслуживает сразу несколько доменов.
- **Общий контентный access checker:** `src/security/rbac/resource_access.py` используется для проверки авторства, публикации, usergroup membership и org scope. Удаление одного consumer не означает, что checker можно удалить.
- **OrganizationConfig — общий JSON-хаб.** Feature toggles, план, tenancy-related settings, брендинг, email и UI-настройки сосуществуют в одной записи; `resolve_feature()` понимает v1/v2 форматы конфигурации.
- **Модели подключаются динамически.** `src/core/events/database.py::import_all_models()` обходит `src/db` и доступный `ee/db`; удаление model-модуля меняет SQLModel metadata и результат миграционной проверки.
- **Миграции не являются механизмом автоматического удаления.** `ensure_schema()` умеет согласовать отсутствующие таблицы/колонки, но потенциально разрушительные изменения оставляет без применения. Удаление моделей не удалит безопасно исторические данные.
- **Startup/shutdown — общий реестр фоновых функций.** `core/events/events.py` импортирует и запускает cleanup, nudges, drip, messaging emails, demo refresh, HLS, captions, RAG и backfill; при удалении фонового сервиса соответствующие startup/shutdown hooks тоже должны быть согласованы.
- **Feature availability влияет одновременно на API и UI.** Backend `features_utils/resolve.py` и deployment mode сопоставляются с Web меню, settings и page routes. Некоторые EE routes на вид присутствуют в Web, но экспортируются из `@ee` и здесь заменены stub.
- **API-контракты генерируются:** удаление или изменение API route затрагивает OpenAPI snapshot/SDK generated schema; package generation не покрывает приватные EE routes.
- **Webhook delivery — общий consumer событий.** Диспетчер вызывается из разных бизнес-сервисов; Zapier создаёт webhook endpoints с `source="zapier"` и использует тот же dispatcher. Удаление Zapier не равнозначно удалению webhooks.

## Что относительно изолируемо

Ниже — оценка архитектурной связанности, не решение об удалении.

1. **`docs/`** — отдельное Next.js/Nextra-приложение; по изученным точкам входа не является runtime-зависимостью Web/API.
2. **`apps/cli`** — отдельное приложение и пакет. Работающий контейнер может запускаться без CLI, но исчезает текущий install/update/backup/dev-инструмент.
3. **`packages/{sdk,react,vue}`** — отдельные публикуемые артефакты, не обязательные для выполнения основной платформы. Удаление затрагивает интеграционный ecosystem и package CI/release.
4. **Zapier adapter** — относительно отделён от generic webhooks: `routers/integrations/zapier.py` повторно использует WebhookEndpoint/dispatcher, поэтому его можно исследовать как отдельную интеграцию, не отождествляя с webhook subsystem.
5. **Отдельные gated-функции** (например, MCP, AI subfeatures, boards, podcasts, paths, playgrounds) имеют различимые роутеры, UI и модели. Однако «отдельный каталог» не означает автономность: у каждого есть зависимости на org, auth/RBAC, storage, feature resolver, startup и миграции.
6. **Org analytics implementation** — в этом checkout она явно EE-only: `services/analytics/analytics.py::track()` делегирует EE hook, а Web analytics route импортируется из `@ee`. Это не делает ненужными `UserActivityDay`, `UserAuditEvent`, PostHog или события, которые вызывают `track()`.

## Удаление с широким радиусом изменений

- **Authentication/Users:** все защищённые API routes, user/org membership, session cookies, MFA, API tokens, notifications, audit, MCP и внешняя авторизация.
- **Organizations/Roles/UserGroups:** tenant isolation, `org_id`-зависимые данные, shared RBAC, feature gating, custom domains, scoped URLs и настройки ресурсов.
- **Courses/Activities:** assignments, completion/certificates, trails/paths, media, video jobs, RAG, search, community links и course notifications.
- **Media/Storage:** файловые контракты, upload/download, streaming/range requests, block assets, submissions и storage migrations.
- **Email sender/delivery:** password reset/verification/invites и несколько независимых фоновых уведомлений.
- **Feature resolver и EE hooks:** даже если отдельная функция исключена, эти слои остаются точками подключения и gating других функций.
- **Migration/startup/config:** нужно синхронно менять model imports, Alembic history, `app.py` router assembly, lifecycle hooks, config, Docker images, CLI templates и тесты.
- **Generated packages:** изменения API/Web требуют проверки generated SDK schema и опубликованного React/Vue renderer; их нельзя корректно оценить только поиском runtime imports.

## Неизвестные места для следующей проверки

1. **EE-код отсутствует в checkout.** Невозможно полностью проследить реализации Payments/store/paywalls, org analytics, Atlas, LTI/SCORM, live sessions, SSO и часть SaaS flow. `ee-stub` подтверждает лишь контракт некоторых frontend imports, не фактическую реализацию.
2. **Production deployment вне репозитория.** Здесь есть Dockerfiles, CLI-generated Compose и GitHub workflows, но не обнаружены полные Kubernetes/Helm/Terraform-конфигурации. В workflow отдельно упоминается внешний pipeline для service images.
3. **Фактические data-retention и cleanup guarantees.** Модели показывают FK/cascade и часть ledger logic, но без анализа всех миграций и object-storage cleanup нельзя безопасно оценить последствия удаления сущностей.
4. **Внешние провайдеры:** не проверялись доступность/контракты Judge0, Stripe, WorkOS, Loops, S3-совместимых хранилищ и отдельных AI моделей.
5. **Feature gates в каждом пути:** статический обзор выявляет центральный resolver, но для удаления функции потребуется отдельно проверить все route handlers, меню, dynamic imports и API-token permissions.
6. **Тестовое покрытие:** по именам тестов можно определить заявленные сценарии, но не полноту assertions. Тесты не запускались, как и миграционные проверки.

Выводы о возможности исключения пока относятся к структуре кода. Для решения по каждому домену потребуется утверждённый product scope, затем отдельная проверка всех references, конфигурационных режимов, миграций, маршрутов, фоновых задач и integration tests этого scope.
