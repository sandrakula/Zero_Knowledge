# ZEROK-7 — демонстрационный веб-интерфейс

## Что реализовано

Статический интерфейс в `web/` проводит пользователя через весь сценарий без
бэкенда: старт, три Python-задачи, демонстрационная проверка, вопросы по
решениям, пример профиля знаний и roadmap. Нужны только браузер и локальный
HTTP-сервер; API-ключи, Docker и платные запросы не используются.

Данные в `web/mock-data.js` используют реальные названия полей схем ZEROK-2:
`Task`, `TaskSet`, `Answer`, `KnowledgeProfile`, `SkillAssessment`, `Roadmap`,
`RoadmapStep` и `Recommendation`. Не входящие в `Task` примеры и стартовый код
лежат отдельно в `taskPresentation`, чтобы не нарушать `extra="forbid"`.
UI-логика находится отдельно в `web/app.js`.

Разбор решения согласован со схемами ZEROK-5 из актуального `main`:
`SolutionQuestion`, `SolutionReview` и `UnderstandingAssessment`. Сам ZEROK-5
не исполняет и не проверяет код — он получает уже известное значение
`Answer.is_correct`, формирует вопросы и рассчитывает понимание. Поэтому UI не
выдаёт успех для произвольного текста.

## Запуск

Из корня проекта:

```powershell
python -m http.server 8000 --directory web
```

Открыть <http://localhost:8000/>. Альтернатива для Windows, если команда
`python` не зарегистрирована:

```powershell
py -m http.server 8000 --directory web
```

## Проверка заглушек

Сетевой сценарий можно выбрать в правой части шапки или передать параметром:

- `http://localhost:8000/` — работа без искусственных сетевых сбоев;
- `http://localhost:8000/?transport=network-error` — каждый тип операции сначала
  завершается демонстрационным сбоем, а кнопка «Повторить» приводит к успеху.

Над редактором доступны четыре явных образца: корректный, неверный результат,
синтаксическая ошибка и ошибка выполнения. Только точное содержимое известных
заглушке образцов получает соответствующий исход. Любой другой код возвращает
`not_evaluated`: он сохранён, но его корректность не определена и переход дальше
заблокирован. Код не анализируется упрощёнными эвристиками и не исполняется.

Для проверки пустого ввода удалите код и нажмите «Проверить решение» либо
оставьте один из ответов на вопросы пустым. Во время искусственной задержки
кнопки блокируются, поэтому повторная отправка невозможна. Код, ответы,
переходы и уже показанные результаты хранятся в `sessionStorage` текущей
вкладки. Кнопка «Начать заново» очищает эту сессию.

## Границы реализации

- Код пользователя не выполняется и никуда не отправляется.
- `checking`, `passed`, `failed`, `error` и `not_evaluated` — состояния UI-адаптера,
  а не выдуманные поля Python-схем. Канонический `Answer` сохраняет свои
  `pending`, `correct` и `incorrect`.
- Подготовленные вопросы различаются по задачам, ссылаются только на конструкции
  точного успешного образца и хранятся в канонической структуре ZEROK-5.
- Формат ответов пользователя на `SolutionQuestion` пока не определён ZEROK-5;
  UI хранит минимальный черновик `answer_id + question_order + content`.
- Результаты тестов, профиль и roadmap — демонстрационные данные, а не оценка
  действий пользователя. Это явно отмечено в интерфейсе.
- Реализации DeepSeek, генерации задач и изолированного исполнения не менялись.
- HTTP-маршруты для ZEROK-8 не предполагаются и не документируются как
  согласованный контракт.

## Точки подключения ZEROK-8

ZEROK-8 должен заменить `MockDiagnosticService` в `web/mock-data.js` адаптером
реального источника данных. UI ожидает методы `getDiagnostic`, `checkAnswer`,
`getDiscussion`, `submitExplanations`, `getProfile` и `getRoadmap`. Конкретные
маршруты, транспорт ошибок и серверное управление сессией предстоит согласовать.
Ответы на задачи уже формируются с полями схемы `Answer`; серверные ответы должны
валидироваться по схемам ZEROK-2 до передачи в отображение.

## Тесты фронтенд-заглушки

Без установки зависимостей:

```powershell
node --test web/mock-data.test.js
```

Тесты покрывают произвольный и пустой код, известный успешный образец,
несовпадение вывода, syntax/runtime error, повторную отправку, релевантность
вопросов и сетевой retry.
